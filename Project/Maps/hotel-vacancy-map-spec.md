# ホテル空室・観光地分布マップツール 仕様書

最終更新：オンデマンド共有検索モデル反映版（巡回・コントリビューター方式から変更）

## 1. 目的
繁忙期などに、好きな日付・好きな場所のホテル空室状況を地図上で検索・可視化し、観光地の分布と重ね合わせることで「空いている宿泊エリア」を見つけやすくする。検索結果は複数人で共有・蓄積される。

## 2. 想定ユーザー・公開方針
- 作成者本人の利用からスタートし、**将来的には一般公開も視野に入れる**
- **ログイン・アカウント登録は不要**。誰でも閲覧できる、Googleマップ的な「付加情報レイヤー」という位置付け
- **個人情報を扱わない**（APIキーはブラウザ内にのみ保持し、サーバーには保存しない）

## 3. 設計の考え方（巡回型 → ユーザー主導型）
日本は広いため、数人による「全国の定期巡回」は現実的でない。
そこで**検索はユーザーがその場で行い、結果だけを共有DBに蓄積**する方式にした。

- ユーザーは地図上で任意の日付・地点（＋半径3/8/12km）を指定して検索
- 検索地点は全国共通のグローバルグリッド（間隔4km・検索半径2.8km/セル）に量子化
- 1セルの結果は「日付×セル」単位でD1に保存され、**別の人が同じ場所を見ると再利用**される
- 同じセルを当日中に誰かが検索済みならAPIを呼ばずにキャッシュを返す
- 利用者が増えるほどカバー範囲が自然に広がる（「たまっていく」モデル）

## 4. 対象範囲
- 地域：日本全国（グリッドは固定バウンディングボックスを持たず、任意の地点に対応）
- 期間：日付を1日単位で指定して検索
- 宿泊施設：楽天トラベル掲載施設

## 5. 主な機能
### 5.1 空室検索機能
- 地図クリックで指定地点を検索。半径は3/8/12kmから選択
- 検索は即時。結果はGeoJSONで返り、地図に反映される
- 同じ地点の再検索は、翌日以降なら最新化（当日中はキャッシュ再利用）

### 5.2 地図表示機能（ヒートマップ）
- 指定日に検索済みのセルを、空室件数に応じて赤（混雑）〜緑（穴場）の円で表示
- 日付を切り替えると、その日に蓄積された結果が表示される

### 5.3 観光地表示機能
- OpenStreetMap Overpass APIから現在の地図表示範囲内の観光地POIを取得し重ねる（ズームレベル9未満では取得しない）

### 5.4 APIキー設定
- 楽天トラベルAPIのキー（アプリID・アクセスキー・任意のアフィリエイトID）をフロントの設定画面で入力
- キーは**ブラウザのlocalStorageにのみ保存**され、検索のAPI呼び出しに使用される（サーバーには保存しない）
- 「キーをテスト」で楽天APIを1回呼んで有効性を確認できる
- サーバー側に共通キー（envシークレット）を設定している場合は、キー未入力のユーザーもそれをフォールバックとして使える

## 6. システム構成
```
[フロントエンド] frontend/index.html（Leaflet.js + CARTOダークタイル）
   ↓ クリック検索 / 蓄積表示 / ホテル一覧（REST + CORS）
[Cloudflare Worker]（無料枠）
   /api/search   : 指定地点をグリッド分解 → 楽天空室検索API → vacancy_cellsに保存
   /api/hotels   : 指定セルの空室ホテル一覧（名前・料金・アフィリエイトURL）→ hotel_detailsに保存
   /api/heatmap  : 指定日の蓄積セルをGeoJSONで返す
   /api/status   : 指定日の蓄積状況
   /api/config   : サーバー側キー設定有無
   /api/settings : キー検証のみ（保存しない）
[Cloudflare D1]（無料枠）
   vacancy_cells : 日付×セル単位の空室件数キャッシュ
   hotel_details : 日付×セル単位の空室ホテル一覧キャッシュ（JSON）
```

## 7. データベース設計（D1）
| テーブル | 役割 |
|---|---|
| `vacancy_cells` | 日付×グリッドセルの空室件数。`PRIMARY KEY(date, lat, lng)`。`fetched_at`で鮮度管理 |
| `hotel_details` | 日付×セルの空室ホテル一覧をJSONで保存。`PRIMARY KEY(date, lat, lng)`。ヒートマップのセルクリック時に当日中は再利用 |

## 8. API仕様（Cloudflare Worker）
| エンドポイント | 説明 |
|---|---|
| `GET /api/search?date=YYYY-MM-DD&lat=..&lng=..&radiusKm=..` | 指定日・地点を検索しGeoJSONで返す（radiusKm省略時3km、上限12km、セル上限40） |
| `GET /api/hotels?date=YYYY-MM-DD&lat=..&lng=..&radiusKm=..` | 指定セルの空室ホテル一覧（名前・料金・アフィリエイトURL）。radiusKmは0.1〜3.0km。当日中はhotel_detailsを再利用 |
| `GET /api/heatmap?date=YYYY-MM-DD` | 指定日に蓄積されたセルをGeoJSONで返す |
| `GET /api/status?date=YYYY-MM-DD` | 蓄積セル数・最終取得日時 |
| `GET /api/config` | サーバー側キー設定有無 |
| `POST /api/settings` | キーの有効性テスト（保存なし） |

- 楽天APIを呼ぶリクエストはヘッダ `x-rakuten-app-id` / `x-rakuten-access-key` / `x-rakuten-affiliate-id` で自分のキーを渡せる。無ければサーバー側envキーにフォールバック
- CORS対応済み（`Access-Control-Allow-Origin: *`、OPTIONSプリフライトあり）
- 429（レート制限）は `/api/search` では `partial:true` でここまでに検索できたセルを200で返す。`/api/hotels` では `{error:"rate_limited"}` で返す

## 9. フロントエンド仕様
- 単一HTMLファイル（`frontend/index.html`）。Leaflet.js（CDN: cdnjs.cloudflare.com）+ CARTOダークタイル
- 主要UI：
  - 宿泊日ステッパー（前日／翌日／日付直接指定）
  - 検索半径セレクタ（3/8/12km）
  - 観光地表示トグル
  - APIキー設定（ブラウザ保存＋キーテスト）
  - 凡例（空き少＝赤 〜 空き多＝緑、観光地＝金ドット）
- 操作：**地図クリック**で検索（未取得セルを検索して蓄積）、**ヒートマップの円クリック**でその場所の空室ホテル一覧（名前・料金・楽天トラベル予約リンク）をポップアップ表示
- `CONFIG.API_BASE` が未設定の場合は**デモモード**でダミーデータ表示
- 外部リソースは許可済みCDN（cdnjs.cloudflare.com）。読み込み失敗時は画面上にエラー表示

## 10. 非機能要件
- コストは無料枠内。楽天APIのレート制限を考慮し、リクエスト間隔・検索半径上限を設定値として持つ
- 個人情報を扱わない（APIキーはサーバーに保存しない、ログイン不要、アクセス解析はCookieレス集計のみ）

## 11. 将来検討
- **検索範囲の拡大**：1回の検索半径を12kmより広げる（セル上限・レート制限とのトレードオフ調整）
- **キャッシュ鮮度のチューニング**：繁忙期（盆・年末など）は当日中でも再取得できるようにするかなど
- **フィルタ**：価格帯・部屋タイプなどでの絞り込み
