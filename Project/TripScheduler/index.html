TripScheduler

地点を指定して動的に組む旅程プランナーと、検索するたびに増えるRouteカタログ、ホテル検索をまとめたページ

緑系の丸=手動登録のRouteカタログ（色は混雑リスクの目安：緑=空いている傾向／黄=やや混雑／赤=激混み想定）、青の四角=「現地プラン作成」タブの検索履歴。マーカーをクリックすると詳細を表示します。

⚠️ file:// で開いています

このページを file:// で直接開くと、ブラウザは Origin: null としてリクエストを送るため、 overpass-api.de 等のサーバーがCORSヘッダーを返さず、 スポット検索が失敗することがあります（コンソールに No 'Access-Control-Allow-Origin' header is present と出ていたら、これが原因です）。

回避策：このフォルダでローカルサーバーを起動してから、 http://localhost:8000/index.html のようなURLで開いてください。 例：npx serve . または python -m http.server 8000。 GitHub Pages等で公開して開くのでも構いません。

出発地から目的地までのルートを作る

出発地・目的地を入力すると、その間の道なりルート（OSRM）沿いにある OpenStreetMap上の観光地・飲食店・Wifi/電源カフェ・温泉銭湯を検索します。 候補から好きなものだけを選んで、名前を付けて「ルートカタログ」に 登録できます（登録したルートは後で組み合わせて複数日の旅程にできます）。 APIキー不要、ブラウザから直接OSM/OSRMに問い合わせます。

楽天トラベルAPI キー設定

キーはこの端末のブラウザ（localStorage）にのみ保存され、サーバーには送信されません。 楽天API側のCORSはブラウザからの直接アクセスを許可していますが、 「アプリ登録」で設定したApplication URLとこのページの実際のURLのRefererが 一致しないと HTTP_REFERRER_NOT_ALLOWED で失敗します。
